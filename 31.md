# NUT-31: Custom Payment Methods

`optional`

`depends on: NUT-04 NUT-05`

---

This document describes minting and melting ecash with custom payment methods that are not otherwise specified in a dedicated NUT. It is an extension of [NUT-04][04] and [NUT-05][05] which cover the protocol steps of minting and melting ecash shared by any supported payment method.

A custom payment method is identified by a lowercase string `{method}` (e.g., `paypal`, `stripe`, `onchain-payment-processor`) that is not already defined in another NUT. The `{method}` string **MUST** contain only ASCII alphanumeric characters, hyphens (`-`), and underscores (`_`), and **MUST** be non-empty.

## Mint Quote

For a custom `{method}`, the wallet includes the following specific `PostMintQuoteCustomRequest` data:

```json
{
  "amount": <int>,
  "unit": <str_enum[UNIT]>,
  "description": <str>, // Optional
  "pubkey": <str>, // Optional
  ... // Additional method-specific fields may be included
}
```

`amount` is the amount of tokens to mint. `unit` is the currency unit. `description` is an optional human-readable description for the payment. `pubkey` is an optional public key for [NUT-20][20] locks. Any additional fields beyond those defined above are method-specific and **SHOULD** be ignored by implementations that do not recognize them.

The mint responds with a `PostMintQuoteCustomResponse`:

```json
{
  "quote": <str>,
  "request": <str>,
  "amount": <int|null>,
  "unit": <str_enum[UNIT]|null>,
  "expiry": <int|null>,
  "pubkey": <str|null>,
  ... // Additional method-specific fields may be included
}
```

Where:

- `quote` is the quote ID
- `request` is the method-specific payment request (e.g., a payment URL, an on-chain address, an account identifier)
- `amount` is the quote amount
- `unit` is the currency unit
- `expiry` is the Unix timestamp until which the quote is valid
- `pubkey` is the public key from the request, if one was included

Any additional fields beyond those defined above are method-specific and **SHOULD** be ignored by implementations that do not recognize them.

### Example

**Request** with curl:

```bash
curl -X POST http://localhost:3338/v1/mint/quote/paypal -d \
'{"amount": 100, "unit": "usd", "description": "Mint 100 USD"}' \
-H "Content-Type: application/json"
```

**Response**:

```json
{
  "quote": "DSGLX9kevM...",
  "request": "https://paypal.me/checkout/token-xyz",
  "amount": 100,
  "unit": "usd",
  "expiry": 1701704757,
  "payer_id": "PAYER123"
}
```


## Mint Settings

The `options` field for custom payment methods **MAY** be present but **SHOULD** be an empty object `{}` if present. Method-specific options can be defined by future NUTs that formalize a custom method.

### Example `MintMethodSetting`

```json
{
  "method": "paypal",
  "unit": "usd",
  "min_amount": 1,
  "max_amount": 50000,
  "options": {}
}
```

## Melt Quote

For a custom `{method}`, the wallet includes the following specific `PostMeltQuoteCustomRequest` data:

```json
{
  "method": <str>,
  "request": <str>,
  "unit": <str_enum[UNIT]>,
  ... // Additional method-specific fields may be included
}
```

`method` is the custom payment method name. `request` is the method-specific payment target (e.g., a bank account identifier, an on-chain address, a payment processor reference). `unit` is the unit the wallet would like to pay with. Any additional fields beyond those defined above are method-specific and **SHOULD** be ignored by implementations that do not recognize them.

The mint responds with a `PostMeltQuoteCustomResponse`:

```json
{
  "quote": <str>,
  "amount": <int>,
  "fee_reserve": <int>,
  "expiry": <int>,
  "payment_preimage": <str|null>,
  "request": <str|null>,
  "unit": <str_enum[UNIT]|null>,
  "change": <Array[BlindSignature]>, // Optional
  ... // Additional method-specific fields may be included
}
```

Where:

- `quote` is the quote ID
- `amount` is the amount to be paid
- `fee_reserve` is the additional fee reserve required for the payment
- `expiry` is the Unix timestamp until which the quote is valid
- `payment_preimage` is a method-specific proof of payment, present once the payment has been completed
- `request` is the payment request for reference
- `unit` is the currency unit
- `change` contains blind signatures for overpaid fees if `outputs` were included in the melt request (see [NUT-08][08])

The mint expects the wallet to include `Proofs` of _at least_ `total_amount = amount + fee_reserve + fee` where `fee` is calculated from the keyset's `input_fee_ppk` as described in [NUT-02][02].

Any additional fields beyond those defined above are method-specific and **SHOULD** be ignored by implementations that do not recognize them.

### Melting Tokens

For a custom `{method}`, the wallet can include an optional `outputs` field in the melt request to receive change for overpaid fees (see [NUT-08][08]):

```json
{
  "quote": <str>,
  "inputs": <Array[Proof]>,
  "outputs": <Array[BlindedMessage]> // Optional
}
```

If the `outputs` field is included and there is excess from the `fee_reserve`, the mint will respond with a `change` field containing blind signatures for the overpaid amount.

### Example

**Melt quote request**:

```bash
curl -X POST https://mint.host:3338/v1/melt/quote/stripe -d \
'{"method": "stripe", "request": "acct_1234567890", "unit": "usd"}'
```

**Melt quote response**:

```json
{
  "quote": "TRmjduhIsPxd...",
  "amount": 99,
  "fee_reserve": 1,
  "expiry": 1701704757,
  "request": "acct_1234567890",
  "unit": "usd",
  "payment_intent": "pi_abc123"
}
```

Check quote state:

```bash
curl -X GET http://localhost:3338/v1/melt/quote/stripe/TRmjduhIsPxd...
```

**Melt request**:

```bash
curl -X POST https://mint.host:3338/v1/melt/stripe -d \
'{"quote": "TRmjduhIsPxd...", "inputs": [...]}'
```

**Successful melt response**:

```json
{
  "quote": "TRmjduhIsPxd...",
  "amount": 99,
  "fee_reserve": 1,
  "expiry": 1701704757,
  "payment_preimage": "proof-of-payment-hash",
  "request": "acct_1234567890",
  "unit": "usd",
  "payment_intent": "pi_abc123"
}
```

### Example `MeltMethodSetting`

```json
{
  "method": "stripe",
  "unit": "usd",
  "min_amount": 1,
  "max_amount": 25000
}
```

## Method-Specific Fields

Custom payment methods **MAY** include additional fields in both requests and responses. These fields are specific to the payment method and are not defined by this NUT. They are included at the top level of the JSON object alongside the standard fields.

Implementations **MUST** ignore any unrecognized fields in requests and responses to preserve forward compatibility. This allows payment methods to evolve without breaking existing clients.

When a custom payment method gains widespread adoption, its method-specific fields **MAY** be formalized in a dedicated NUT that promotes them to well-defined request and response structures.

## Websocket Notifications

Custom payment methods **MAY** support websocket subscriptions via [NUT-17][17]. The subscription kinds for a custom method `{method}` are:

```ts
"{method}_mint_quote"   // e.g., "paypal_mint_quote"
"{method}_melt_quote"   // e.g., "stripe_melt_quote"
```

The `filters` are an array of quote IDs to receive updates for.

### Example

Subscribe to mint quote updates:

```json
{
  "jsonrpc": "2.0",
  "id": 0,
  "method": "subscribe",
  "params": {
    "kind": "paypal_mint_quote",
    "filters": ["DSGLX9kevM..."],
    "subId": "Ua_IYvRHoCoF_wsZFlJ1m4gBDB--O0_6_n0zHg2T"
  }
}
```

Mints signal websocket support for custom methods via the [NUT-17][17] settings:

```json
"nuts": {
  "17": {
    "supported": [
      {
        "method": "paypal",
        "unit": "usd",
        "commands": [
          "paypal_mint_quote",
          "paypal_melt_quote",
          "proof_state"
        ]
      }
    ]
  }
}
```

## Cached Responses

Custom payment method endpoints **MAY** support response caching via [NUT-19][19]. The cached endpoints are:

```json
"nuts": {
  "19": {
    "ttl": 60,
    "cached_endpoints": [
      {
        "method": "POST",
        "path": "/v1/mint/paypal"
      },
      {
        "method": "POST",
        "path": "/v1/melt/paypal"
      }
    ]
  }
}
```

## Error Handling

Mints **MUST** return errors using the standard error response format. Mints **SHOULD** distinguish between an invalid payment method (not configured or unparseable request) and an unsupported payment method (recognized but not available for the requested unit or operation).

## Failed Melt Handling

If the external payment fails during a melt operation, the mint **MUST** release the reserved input proofs and reset the quote state to `UNPAID`. The wallet **SHOULD** be able to retry the melt with the same proofs.

## Method-Specific Extra Fields

Custom payment methods **MAY** include an `extra` field in mint and melt quote requests and responses. The `extra` field is a JSON object containing method-specific data. The mint **MUST** forward the `extra` field to the payment processor and include any method-specific fields from the processor's response in the quote response. The mint **SHOULD NOT** validate or interpret the `extra` field.

## Amount Precision

For fiat-denominated units (e.g., `usd`, `eur`), the `amount` field **SHOULD** represent the value in the smallest currency unit (e.g., cents). For example, `"amount": 100` with `"unit": "usd"` represents $1.00 USD.
